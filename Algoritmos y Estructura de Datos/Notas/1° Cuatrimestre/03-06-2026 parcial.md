PUNTOS A REPASAR

Precedencia en booleanos: el orden de evaluacion es NOT > AND > OR > == , pero ojo porque == tiene MAS precedencia que && y ||. Eso significa que "true && false == false" no se lee como "(true && false) == false" sino como "true && (false == false)". Los parentesis siempre ganan sobre todo, o sea que lo que esta adentro de () se resuelve primero sin importar que operador sea.

La trampa del char '0': el caracter '0' (con comillas simples) NO es igual al entero 0. '0' vale 48 en ASCII. Siempre que veas comillas simples es un numero ASCII, no el valor literal. '1' = 49, '2' = 50, y asi. En cambio 0 sin comillas es el entero cero.

Division entera trunca hacia abajo: 100 / 6 en C++ da 16, no 16.67. El resultado siempre es entero y se cortan los decimales. Por eso 100 / 6 * 6 da 96, no 100. Lo que SI siempre da verdadero es la identidad: (a % b) + (a / b) * b == a, porque el resto y el cociente son consistentes entre si.

Espaciado uniforme en ASCII: 'z' - 'a' == 'Z' - 'A' es verdadero porque las letras del abecedario estan en orden consecutivo tanto en mayusculas como en minusculas, con la misma distancia entre ellas (25). Lo que cambia es el offset entre mayusculas y minusculas, que es siempre 32. O sea 'a' - 'A' == 32.

Unsigned con numeros negativos hace wrap-around: si guardas -1 en un unsigned int de 32 bits no se vuelve 1 ni falla, se convierte en 4294967295 (el maximo valor). Si restas 1 a un unsigned que vale 0, pasa lo mismo, salta al maximo. Esto se llama overflow circular y es un comportamiento definido en unsigned (a diferencia del int donde es indefinido).

Notacion cientifica, cuidado con el exponente: 3000 es 3e3 (tres por diez a la tres), no 3e4. 3e4 es 30000. Siempre conta los ceros para verificar.

String length hay que contar bien: "AED" tiene 3 caracteres (A, E, D). "Hola Ana!" tiene 9 (H, o, l, a, espacio, A, n, a, signo de exclamacion). El espacio y la puntuacion cuentan como caracteres.

Comparacion de strings es lexicografica (como el diccionario): va letra por letra comparando el valor ASCII. Como las mayusculas tienen menor valor ASCII que las minusculas ('A' = 65, 'a' = 97), un string que empieza con mayuscula es menor que uno que empieza con minuscula. "ABC" < "abc" es verdadero.

climits se escribe con s al final: el header correcto es `#include <climits>`, no `<climit>`. Sin la s no existe.

Identidad de De Morgan: !(A && B) es lo mismo que (!A || !B), y !(A || B) es lo mismo que (!A && !B). Sirve para reescribir negaciones de expresiones compuestas.

Doubles exactos en binario: solo son exactos los numeros cuyo denominador es una potencia de 2. 0.5 = 1/2 exacto, 0.25 = 1/4 exacto, 0.125 = 1/8 exacto. 0.1 = 1/10 NO exacto (10 tiene factor 5). 1.0, 2.0, 4.0 exactos. Regla rapida: si el denominador es 2, 4, 8, 16... es exacto. Si tiene 3, 5, 6, 7, 9, 10... no lo es.

Operador ternario: condicion ? valor_si_true : valor_si_false. Ejemplo: x < 0 ? -x : x devuelve -x si x es negativo, x si no. Es un if comprimido en una sola expresion.

**Prototipo vs implementacion**: el prototipo es solo la firma (tipo, nombre, parametros) sin cuerpo, termina en ; . La implementacion es la firma MAS el cuerpo con {}. Ejemplo: prototipo = "double f(double);" , implementacion = "double f(double x){ return 2*x+1; }".

Argumento vs parametro: el parametro es la variable en la definicion de la funcion (lo que esta en los () cuando defines la funcion). El argumento es el valor concreto que le pasas al llamarla. En "double f(double x)", x es el parametro. En "f(3)", 3 es el argumento.

Casting de tipo en division: (double)7/2 convierte el 7 a double antes de dividir, resultado es 3.5. Lo mismo pasa si uno de los dos es double: 7.0/2 y 7/2.0 dan 3.5. Solo 7/2 (ambos int) da 3 por division entera.

float vs double: los dos son tipos de punto flotante, pero double tiene mas precision. En esta materia se usa double siempre. float no es la respuesta correcta cuando se pide un tipo para valores continuos como velocidad o temperatura.

Presion arterial en mmHg es un entero: se mide en numeros enteros (120, 80). No es continuo. Tipo correcto: unsigned o int, no double.

NDEBUG: si se define antes del `#include <cassert>`, deshabilita todos los asserts (el compilador los ignora). Se usa en produccion para no gastar tiempo ejecutando pruebas. Se activa con -DNDEBUG al compilar, sin modificar el codigo fuente.

Funcion Cerca y toCelsius — como se escriben:

```cpp
#include <cassert>

// Prototipo (declaracion)
// El nombre del parametro puede ser lo que quieras: tolerancia, epsilon, delta, margen...
// El profe usa epsilon (e) por convencion matematica, pero es lo mismo.
double toCelsius(double fahrenheit);
bool Cerca(double a, double b, double tolerancia = 0.001);

int main() {
    // Celsius exactos (se pueden comparar con ==)
    assert( toCelsius(32)  == 0.0   );
    assert( toCelsius(212) == 100.0 );

    // Celsius inexactos (hay que usar Cerca)
    assert( Cerca( 17.7778, toCelsius(64) )         );  // tolerancia default 0.001
    assert( Cerca(-17.7778, toCelsius(0) )          );
    assert( Cerca( 17.7778, toCelsius(64), 0.0001 ) );  // tolerancia mas chica
}

// Implementacion de toCelsius
// Convierte grados Fahrenheit a Celsius
// Formula: C = (F - 32) * 5/9
// Importante: 5.0/9.0 y NO 5/9 (division entera daria 0)
double toCelsius(double fahrenheit) {
    return 5.0 / 9.0 * (fahrenheit - 32);
}

// Implementacion de Cerca
// Devuelve true si b esta dentro del rango [a - tolerancia, a + tolerancia]
// El tercer parametro tiene valor por defecto: si no lo pasas, usa 0.001
bool Cerca(double a, double b, double tolerancia) {
    return (a - tolerancia) <= b && b <= (a + tolerancia);
}
```

# char y ASCII

`char` internamente **es un número entero**, y `'a'` es solo la forma de escribir el número `97`. Son equivalentes para el compilador.

> Si hacés `cout << 'a'` → imprime `a` (lo interpreta como carácter)  
> Si hacés `cout << (int)'a'` → imprime `97` (lo forzás a mostrar el número)  
> El char se guarda como **número en binario/decimal internamente**, lo que imprimís depende de cómo se lo pedís.

**`assert('a' + 1 == 'b')`** → ✅ Correcto.

**`assert('Z' - 'A' == 25)`** → ✅ Correcto. Z es 90, A es 65, 90−65 = 25.

**¿Puede `char` guardar 200? ¿Y 300?**

- `char` tiene **8 bits** → rango de **−128 a 127** (versión signed, la más común)
- **200 NO cabe** en un signed char (excede 127). Se desbordaría.
- **300 tampoco cabe** ni siquiera en unsigned char (máximo 255).
- La respuesta correcta para el examen: _"char tiene 8 bits, puede representar 256 valores. Como signed va de −128 a 127, el 200 no cabe."_

# Double y notación científica

La notación `1e3` significa **1 × 10³**. Es solo otra forma de escribir un número `double`:

| Assert                   | Cálculo   | Resultado |
| ------------------------ | --------- | --------- |
| `assert(1e3 == 1000.0)`  | 1 × 10³   | ✅ TRUE    |
| `assert(1.5e2 == 150.0)` | 1.5 × 10² | ✅ TRUE    |
| `assert(2e-1 == 0.2)`    | 2 × 10⁻¹  | ✅ TRUE    |
| `assert(1e0 == 1.0)`     | 1 × 10⁰   | ✅ TRUE    |

**Sobre la imprecisión del double:** `double` tiene _más_ decimales que `float`, pero eso **no significa que sea exacto**. El problema es que la computadora guarda números en **binario**, y `0.1` en binario es como `1/3` en decimal — una fracción que se repite infinitamente. La computadora lo _aproxima_ y ese error se acumula. Por eso `0.1 × 10 ≠ 1.0` exactamente. Tu TP1 prueba exactamente esto:

```cpp
assert(0.1 + 0.1 + ... + 0.1 != 1.0);  // ✅ TRUE — la suma NO es exactamente 1
```


# Tipos de datos

**¿Por qué temperatura es `double` y no punto fijo?**  
La clasificación es:

- **Contable** (enteros, como cantidad de personas) → `int`, `unsigned`
- **Contable con decimales fijos** (plata, como $1.50) → **punto fijo** (siempre 2 decimales)
- **No contable / continuo** (temperatura, probabilidad, volumen) → **`double`**

La temperatura es **continua** — puede ser 36.6°, 36.61°, 36.612°... No tiene una cantidad fija de decimales. Por eso `double`.

El precio **sí tiene decimales fijos** (centavos = 2 dígitos), por eso punto fijo y **no** `double` (que añadiría error de redondeo al manipular plata).
